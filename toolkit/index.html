Toolkit · v0.5

The TurkicNLP Toolkit

A modular, pip-installable Python library for the whole Turkic language family. Text and speech go in; tokens, morphemes, morphology, POS tags, dependency trees, entities, translations, embeddings and transcripts come out of one Stanza-style pipeline.

24 languages 15 processors 7 backend families Python 3.10 – 3.12 Apache 2.0
View on GitHub → PyPI Paper

Installation

A small core, plus one extra per component group:

$ pip install turkicnlp            # core
$ pip install "turkicnlp[all]"     # all text components
$ pip install "turkicnlp[all,asr]" # + speech (own env)

Models are downloaded at runtime into ~/.turkicnlp, never bundled in the pip package. All extras →

Installation

Install only what you need

Requires Python 3.10 – 3.12. Installation tests run on Ubuntu, macOS and Windows for every push.

ExtraAdds
turkicnlpTokenization, rule-based processing, transliteration, CoNLL-U I/O
[hfst]Apertium FST morphology (Linux, macOS)
[stanza]Stanza models: tokenize, POS, lemma, depparse, NER
[transformers]Glot500 POS / parsing / morphology models
[translation]NLLB-200 embeddings and machine translation
[lid]GlotLID language identification
[all]All text components above (Linux, macOS)
[asr]Speech recognition with Omnilingual ASR
[dev]pytest, black, ruff, mypy

Two tested environments

Text: [all], with torch 2.10, numpy 2 and transformers 5.

Speech + text: [all,asr]. omnilingual-asr pins torch 2.8, numpy 1.26 and transformers 4.57. Every text component also works with these versions.

Lock files for both are in requirements/.

Don't add [asr] to an existing text environment. It downgrades torch, numpy and huggingface_hub, which breaks transformers 5. Create a fresh environment instead.
Windows: everything except Apertium FST morphology works natively. hfst has no Windows wheels, so use WSL if you need FST morphology.
Quick start

Up and running in three steps

1

Install the library

$ pip install "turkicnlp[all]"
2

Download models for your language

The model catalog knows which backend to fetch for each language and script.

import turkicnlp

turkicnlp.download("kaz")
3

Build a pipeline and annotate text

Dependencies between processors are resolved automatically.

nlp = turkicnlp.Pipeline("kaz", processors=["tokenize", "pos", "lemma", "depparse"])
doc = nlp("Мен мектепке бардым.")

print([(w.text, w.upos, w.lemma) for w in doc.words])
# [('Мен', 'PRON', 'мен'), ('мектепке', 'NOUN', 'мектеп'),
#  ('бардым', 'VERB', 'бар'), ('.', 'PUNCT', '.')]

print(doc.to_conllu())          # or doc.to_dict(full=True)

Sensible defaults, full control

Pipeline("kaz") without processors= loads the language's default set: tokenizer, morphology, POS, lemma, features, parsing and NER. Large or optional components (translation, embeddings, ASR, subword tokenization, LLM tasks) load only when you ask for them.

  • Pick a backend per processor: pos_backend="multilingual_glot500_model"
  • Pass options as <processor>_<option>: translate_tgt_lang="eng"
  • Batch processing: nlp.batch(texts, batch_size=32)
  • Provenance: doc._processor_log and word._provenance record which backend produced each value
  • Input in a script without models, such as Uzbek Cyrillic or Kazakh Latin, is transliterated, and results map back to your original text and offsets

Jupyter notebooks for every component: turkic-nlp-code-samples.

Speech recognition · new

From audio to annotated text in 20 Turkic languages

SpeechRecognizer wraps Meta's Omnilingual ASR behind TurkicNLP conventions: ISO 639-3 codes in, transcripts in each language's own script out. Long recordings are split at pauses.

import turkicnlp

asr = turkicnlp.SpeechRecognizer(model_card="omniASR_LLM_1B")
texts = asr.transcribe(["kaz_sample.wav", "tur_sample.wav"],
                       lang=["kaz", "tur"], batch_size=2)
# ['мен бүгін мектепке бардым алматы қазақстанның ең үлкен қаласы',
#  "bugün hava çok güzel ali dün ankara'ya gitti"]

# Ask for another script: Kazakh in the 2021 Latin alphabet
asr.transcribe("kaz_sample.wav", lang="kaz", script="Latn")

# Speech → text → analysis in one pipeline
nlp = turkicnlp.Pipeline("kaz",
    processors=["asr", "tokenize", "pos", "lemma", "depparse"])
doc = nlp.from_audio("kaz_sample.wav")
print(doc.audio_segments)   # time-aligned pieces

LLM backend · new

Use any LLM for languages without trained models

Five processors can run on a large language model for all 24 languages, including Khakas, Tuvan and Nogai, which have no other neural models. Point the toolkit at a local vLLM or Ollama server, OpenAI, Claude or an in-process Hugging Face model.

BackendWhat the LLM does
morph=llmLemma, UPOS and UD features for every token
morph=apertium_llmChooses one of the FST's readings for ambiguous words. It can't invent an analysis.
ner=llmEntity spans over the toolkit's tokens, with configurable labels
translate=llmTranslation into any target language or script
sentiment=llmPositive, negative or neutral, or your own labels
spellcheck=llmSpelling correction, guarded against rewrites
 
nlp = turkicnlp.Pipeline(
    "kaz",
    processors=["tokenize", "morph", "ner", "translate"],
    morph_backend="llm", ner_backend="llm",
    translate_backend="llm", translate_tgt_lang="eng",
    llm_model="qwen2.5:7b",                      # local Ollama
    llm_base_url="http://localhost:11434/v1",
)
# or: llm_provider="anthropic", llm_model="claude-sonnet-4-6"

# Free-form questions with the toolkit's analysis as context
turkicnlp.llm.ask("Explain the verb form.", doc=doc)

Answers are validated against the toolkit's tokens and retried once with feedback. Unusable answers are left empty rather than guessed. Prompts are versioned JSON files you can replace. Only validated answers go into a local cache.

LLM quality varies a lot between languages: usually good for Turkish, Kazakh, Uzbek and Azerbaijani, often weak for Khakas, Tuvan, Nogai or Kumyk. Evaluate a model on your language first, and remember that text goes to whichever server you configure.
Morphology & segmentation

Three ways into Turkic morphology, and a hybrid of them

Apertium finite-state transducers give precise analyses where the lexicon covers a word. Glot500 neural models cover the rest. The MorphemeTokenizer combines both to split words into labelled surface morphemes.

🧬

Apertium FST · morph

Transducers for 20 languages, loaded with Python-native HFST. No system Apertium install needed. Precompiled from upstream by CI, with Apertium → UD tag mapping for every language.

🧠

Glot500 neural · morph_neural

One multilingual model gives UPOS, UD features and lemmas for 22 languages: 20 trained, plus zero-shot Karakalpak, Karachay-Balkar and Nogai.

✂️

Morpheme-aware subwords · sp_tokenize

SentencePiece over morpheme-segmented text, so subword pieces never cross morpheme boundaries. Use it to train language models on Turkic text.

from turkicnlp.processors.morpheme_tokenizer import MorphemeTokenizer

tok = MorphemeTokenizer(lang="tur"); tok.load()
tok.segment("evlerinden").labeled
# [('ev', 'STEM'), ('ler', 'PLUR'), ('in', 'POSS.2SG'), ('den', 'ABL')]

tok = MorphemeTokenizer(lang="kaz"); tok.load()
tok.segment("оқығандар").labeled
# [('оқы', 'STEM'), ('ған', 'PTCP.PST'), ('дар', 'PLUR')]

tok = MorphemeTokenizer(lang="uzb"); tok.load()
tok.segment("bolalarning").labeled
# [('bola', 'STEM'), ('lar', 'PLUR'), ('ning', 'GEN')]

How the hybrid works

Every Apertium reading is turned into a segmentation by matching its tags against language-specific suffix allomorph tables, which encode vowel harmony, consonant alternations and buffer consonants. The tokenizer keeps the reading that explains the whole word, breaking ties by agreement with the neural lemma and POS. When the transducer has no reading, it segments the neural analysis instead.

Exact segmentation483 words · 20 langs
Hybrid (FST + neural)89%
Apertium only79%
Neural only68%

Allomorph tables cover 23 languages. The FST path is available for the 20 with a transducer.

Translation & embeddings

NLLB-200 translation and sentence vectors

One shared NLLB-200 (600M) model serves translation and 1024-dimensional embeddings for 11 Turkic languages. It's downloaded once and kept in memory once.

# Turkish → English
nlp = turkicnlp.Pipeline("tur", processors=["translate"],
                         translate_tgt_lang="eng")
doc = nlp("Bugün hava çok güzel ve parkta yürüyüş yaptım.")
print(doc.translation)

# Sentence embeddings for similarity and retrieval
embed = turkicnlp.Pipeline("tur", processors=["embeddings"])
doc = embed("Parkta yürüyüş çok güzeldi.")
len(doc.embedding)   # 1024

translate_tgt_lang takes ISO 639-3 ("eng", "kaz") or FLORES-200 codes ("kaz_Cyrl"). For any of the 24 languages, translate_backend="llm" translates with an LLM instead.

Language identification

Tell closely related languages apart

The GlotLID FastText model knows 1,000+ language labels. By default, LanguageDetection restricts its predictions to the Turkic languages TurkicNLP supports.

import turkicnlp

lid = turkicnlp.LanguageDetection()      # Turkic label set by default
labels, probs = lid.predict("salam, hemmelere!", k=3)

# Or limit to an explicit label set
lid = turkicnlp.LanguageDetection(languages=[
    "__label__eng_Latn", "__label__tur_Latn", "__label__kaz_Cyrl",
])
lid.predict("Merhaba dünya!", k=1)

Script-aware labels

Labels combine language and script (kaz_Cyrl, uig_Arab), so you get the language and the writing system in a single step. TurkicNLP maps its codes to GlotLID's where they differ: Uzbek is uzn, North Azerbaijani is azj.

Pair it with automatic script detection in the pipeline to route mixed-language collections to the right models.

Scripts & transliteration

Latin, Cyrillic, Perso-Arabic, Runic and the Common Turkic Alphabet

Bidirectional conversion for every multi-script language, a shared Common Turkic Alphabet view for 23 languages, and Old Turkic runes.

from turkicnlp.scripts import Script
from turkicnlp.scripts.transliterator import Transliterator

Transliterator("kaz", Script.CYRILLIC, Script.LATIN).transliterate("Қазақстан Республикасы")
# Qazaqstan Respublikasy

Transliterator("uzb", Script.LATIN, Script.CYRILLIC).transliterate("Özbekiston Respublikasi")
# Ўзбекистон Республикаси

Transliterator("uig", Script.PERSO_ARABIC, Script.LATIN).transliterate("مەكتەپ")
# mektep

Transliterator("tuk", Script.LATIN, Script.COMMON_TURKIC).transliterate("Türkmen dili baýdyr")
# Türkmen dili baydır

Transliterator("otk", Script.OLD_TURKIC_RUNIC, Script.LATIN).transliterate("𐱅𐰇𐰼𐰚")
# törk

Coverage

Cyrillic ↔ Latin: Kazakh (2021), Uzbek, Azerbaijani, Tatar (Zamanälif), Turkmen, Karakalpak (2016), Crimean Tatar
Perso-Arabic ↔ Latin ↔ Cyrillic: Uyghur (ULY, Uyghur Cyrillic)
Latin → Perso-Arabic: Ottoman Turkish
Runic → Latin: Old Turkic (Orkhon-Yenisei)
Native script → CTS: all languages except Old Turkic (23)

Uzbek Latin uses ö, ğ, ş, ç throughout the toolkit. Pretrained models keep their training spelling internally, and adapters convert input and output automatically.

Design

Built to be extended

TurkicNLP follows Stanza's architecture: Pipeline → Document → Sentence → Token → Word, mapping one-to-one to CoNLL-U. Every processor declares what it PROVIDES and REQUIRES, and the pipeline resolves the order.

One owner per field. The last processor that provides a field owns it, for example pos owns UPOS. Values from earlier processors are kept in word._provenance, so you can compare the Apertium and Stanza analyses of the same word.

Script-aware. Models are keyed by lang/script/processor/backend. A packaged catalog says what exists, and turkicnlp.download() fetches what's missing.

# Execution order
asr → script_detect → transliterate
  → tokenize → spellcheck → mwt
  → morph → morph_neural → pos → feats
  → lemma → depparse → ner
  → embeddings → sentiment → translate
  → transliterate_back

# Model storage
~/.turkicnlp/models/
  kaz/Cyrl/morph/apertium/      # GPL-3.0, separate
  multilingual/                 # Glot500 checkpoints
  huggingface/                  # Glot500 backbone, NLLB
  stanza/, stanza_custom/
