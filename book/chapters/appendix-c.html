Appendix C — Turkic Language Reference

NoteWhat This Appendix Covers

This appendix separates language identifiers, writing systems and computational evidence: identifiers and scope (Section C.1), the evidence needed before calling a resource available (Section C.2), a script reference (Section C.3) and the typological properties the chapters use (Section C.4).

The language table lists 23 contemporary languages. It differs from the 24 entries of TurkicNLP 0.5.0 (Chapter 1): the table adds Shor (cjs) and Chulym (clc), which the toolkit does not cover, and leaves out the toolkit’s historical Ottoman Turkish (ota) and Old Turkic (otk) and its separate South Azerbaijani entry (azb). For toolkit coverage, use its versioned registry; for corpus or model labels, use a resource-specific crosswalk.

C.1 Language Identifiers and Scope

aze (Azerbaijani) and uzb (Uzbek) are macrolanguage identifiers; resources may instead use North/South Azerbaijani (azj/azb) or Northern/Southern Uzbek (uzn/uzs). alt denotes Southern Altai, not every variety called Altai. Do not join corpus labels, Wikipedia editions, Hub tags and toolkit codes by string substitution. Record a many-to-one or one-to-many mapping explicitly.

Speaker estimates need a source table or page, reference year, geography and a definition such as first language, self-reported ability or total speakers. Estimates with different definitions cannot support a single ranking, so this table omits them. Glottocodes also await individual verification. Consult the ISO 639-3 registry and Glottolog for identifiers. The codes here were checked against an installed ISO dataset, rather than a fresh registry snapshot.

C.2 NLP Resource Evidence

MMS, for example, releases Chuvash and Crimean Tatar TTS checkpoints (Chapter 11); their suitability for production needs separate testing. The five-language audit in Section 17.6 records availability, unknowns and failed queries separately. Verify model architecture before assigning a label such as “BERT-class”, and retain each resource’s licence and task type.

C.3 Script Reference

C.3.1 Latin Characters and Letter Marks

Turkish dotted İ/i and dotless I/ı need locale-aware casing. Azerbaijani Latin ə/Ə (U+0259/U+018F) must not be confused with Cyrillic ә/Ә (U+04D9/U+04D8). Similar appearance does not imply identical code points or script.

Uzbek oʻ/gʻ and the tutuq sign appear with several digital apostrophe-like characters. Choose a declared encoding convention for a derived copy, retaining the original; using U+0027 does not by itself prove that every tokeniser will segment incorrectly. The context-sensitive search-key helper in Section 4.3 only normalises o/g letter marks and leaves other punctuation alone.

Kazakh Latin schemes are versioned proposals and orthographic conventions, not interchangeable transliterations. Use the dated sources in Chapter 3 and record the chosen converter instead of combining apostrophe, acute and later diacritic inventories into one “current alphabet”.

C.3.2 Cyrillic Characters

The table gives no single IPA value per character: pronunciation and phonemic analysis depend on the language. Kazakh қ/ғ are not letters of the Kyrgyz alphabet. Chapter 2’s source-specific vowel table and Chapter 5’s harmony descriptions provide the linguistic context.

C.3.3 Perso-Arabic Uyghur

Distinguish vowel letters from sequences that include an initial hamza carrier; strings such as ئو contain more than one Unicode code point. Preserve right-to-left text logically, including joining behaviour and meaningful controls. Inspect NFC, code points and rendered output separately. Removing every invisible control as “noise” can damage text. Conversion to ULY or a Cyrillic convention needs a declared scheme and loss report (Chapter 3).
